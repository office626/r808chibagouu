# MVP範囲

## MVP定義

### 目的

入口が二つに分かれたサイトとして、支援者が行政情報の収集を分担でき、県民が優先市町村の被害ログといまの支援策を見られることを確かめる。

### 対象ユーザー

- 支援者：CTZCメンバー
- 県民：優先市町村の住民（まず茂原市。枠は全市町村）

### 成功の定義

- トップで県民と支援者が迷わず分かれる
- 運営者以外から、収集タスクへの手挙げまたはアイデアが出る
- 優先市町村に、公式出典付きの被害ログと「いまの支援策」が載っている

## スコープ

### MVP に含める ✅

| 機能 | 理由 |
|------|------|
| トップの二つの入口 | 両面を持つサイトの約束 |
| 支援者ホーム、Slack、意見箱、やること一覧 | 情報共有と参加の最小構成 |
| 行政情報の収集を募集項目にする | 篠田さん：シビックテックの役割 |
| 県民ホーム、市町村一覧、全市町村のページ枠 | 県全域を対象にする |
| 被害状況ログ（時系列、上書きしない） | 県民向けの過去ログと現在 |
| いま受けられる支援策（受付状態付き） | 生活支援へ移った問い合わせに応える |
| 生活再建の段取り（共通の型） | 罹災証明の前後、修理か仮設か |
| 県全域の支援策ページ | 共通制度を複製しない |
| 最終更新日と有志運営の明示 | 信頼と鮮度 |

### MVP に含めない ❌

| 機能 | 理由 | 対応時期 |
|------|------|----------|
| 全市町村のログ・制度の完備 | 1名では不可能 | Phase 2 |
| QA型ナビゲーター | 制度データが先 | Phase 2 |
| いまのフェーズの全市町村自動判定 | 公式確認が前提 | Phase 2 |
| ユーザー登録・ログイン | 閲覧のみなら不要 | Phase 2 |
| サイト上での投稿・編集 | シートで代替 | Phase 2 |
| 地図ダッシュボード | データ整備が前提 | Phase 3 |
| 多言語対応 | 優先度が低い | 将来検討 |
| 罹災調査システムそのもの | 行政の領域（能登のタブレット等） | 対象外 |

## タイムライン（目安）

| フェーズ | 時期 | 内容 |
|----------|------|------|
| MVP | 即時 | 二入口。支援者の場。県民側は枠＋茂原市など優先市町村のログと支援策 |
| Phase 2 | 〜1ヶ月 | 市町村を分担して埋める。QAナビ。フェーズ表示 |
| Phase 3 | 状況次第 | 地図など追加の見える化 |

## 制約事項

| 制約 | 内容 |
|------|------|
| 人的リソース | 現在1名 |
| 予算 | なし |
| 時間 | 速度が最優先 |
| 情報の正確性 | ログも制度も公式リンク必須。篠田さん報告の金額・日数は裏取り後 |
| 市町村数 | 枠は全市町村。中身は分担 |

## リスクと対策

| リスク | 対策 |
|--------|------|
| 二つの面が混ざって県民が迷う | 入口と主ボタンを分ける。受け入れ条件で担保する |
| 未確認の現地報告を事実として出す | ログは公式URLがある件だけ公開する |
| 運営1名が息切れする | ログは「日時・要約・URL」の追記だけにする |
| 全市町村が空 | 収集タスクを市町村単位の募集にする |
| 袖ケ浦・もばらと重複する | 公開前に連絡し、拡張とクレジットで位置づける |
