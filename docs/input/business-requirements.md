# ビジネス要件

## 1. 課題定義

### 解決する課題

令和8年8月の千葉豪雨の発生を受け、CTZCメンバーや技術を持つ有志の間に「千葉県のために何かしたい」という意思がある。しかしその意思を集約し、具体的な動きに変換する場が存在しない。

具体的には次が起きている。

1. **アイデアが流れて消える** — Slack の提案が蓄積されない
2. **動きが見えない** — 誰が何に取り組んでいるか外から分からない
3. **参加の入口がない** — 有志が人手の要る場所を知らない
4. **自分に使える支援策が分からない** — 国・県・市町村・社協の制度が分散している
5. **被害の経過が残らない** — 公式サイトは最新情報で上書きされ、朝のパトロール結果や節水制限の開始など、過去の状況を後から辿れない
6. **生活再建の段取りが見えない** — 問い合わせは避難支援から生活支援へ移るが、罹災証明書の交付まで時間がかかり、その間に何をすればよいか住民に届きにくい

### 課題の深刻度

災害対応は時間との勝負である。生活再建の制度は申請開始まで日数がかかり、見つけられないこと自体が被害を長引かせる。シビックテックもばら篠田さんによると、茂原市では住宅被害調査から罹災証明書交付まで最低でも2週間、仮設住宅か修理の申請受付まで災害からおよそ1ヶ月かかる、という課題がある（**[要公式確認]**）。その空白期間に、行政が出した情報を集め、県民に分かりやすく渡すことがシビックテックの役割になる。

### 課題が発生する状況

発災直後（避難）から、災害対策本部の情報集約、災害救助法の適用、内閣府の被害状況調査、罹災証明、応急修理・応急仮設の受付へとフェーズが移る全期間。特に「避難が一段落し、生活再建の問い合わせが増える」時期。

## 2. 市場環境

### 既存の代替手段

| 手段 | 現状 |
|------|------|
| Slack（[CTZCチャンネル](https://civictechzenchiba.slack.com/archives/C0BPSMN4L5D)） | すでに設置済み。会話は成立するが、蓄積・一覧性がない |
| 千葉県・各市町村の公式サイト | 一次情報として信頼できるが、情報が各所に分散している |
| [災害支援ナビゲーター（袖ケ浦市版）](https://civictechsodegaura.org/saigai/) | 質問に答えると適用可能性のある制度が一覧される。対象は袖ケ浦市。今回は県全域・全市町村が必要 |
| SNS（X等） | 速報性はあるが、信頼性の判定が難しく、流れて消える |

### 既存手段の課題

Slackは「会話」のツールであり「蓄積・公開」のツールではない。また、クローズドな場であるため、参加していない人からは中の動きが一切見えない。

行政サイトは一次情報としては正しいが、実施主体が多岐にわたるため、住民が自分のケースに当てはまる制度を判別しにくい。これが袖ケ浦のナビゲーターが解いた課題であり、今回は同じ構造を県全域に広げる。

### 取り込む先行取組（シビックテック袖ケ浦）

[シビックテック袖ケ浦](https://civictechsodegaura.org/) は、令和元年台風15号を受けて「災害支援ナビゲーター」を公開した。内閣府の防災情報と袖ケ浦市の情報を基に、質問に答えていくと受けられる可能性のある支援制度が一覧される。最終的な適用可否は各機関の判断である旨を明示したうえで、生活再建の手がかりを届ける設計である。

今回のポータルでは、袖ケ浦市単体ではなく **千葉県全域の制度** と **全市町村の個別ページ** を作る。袖ケ浦の資産は次のように使う。

| 資産 | 使い方 |
|------|--------|
| [災害支援ナビゲーター本体](https://civictechsodegaura.org/saigai/) | 質問→制度一覧という体験の原型 |
| [ソース（GitHub: SaigaiAId）](https://github.com/kanawha-st/SaigaiAId) | ローカライズ可能な実装。団体名・災害種別・QAデータを差し替えて再利用を検討する |
| [ローカライズ手順](https://civictechsodegaura.org/archives/597) | 非エンジニアでも制度データを差し替えられる運用の参考 |
| [能登半島地震版](https://civictechsodegaura.org/archives/883) | 地域を越えたボランティアと共同で別災害へ展開した実績。CTZCとの連携モデルの先例 |

公開前にシビックテック袖ケ浦へ連絡し、再利用・共同編集・クレジットの扱いを確認する。重複ではなく、県全域への拡張として位置づける。

### 取り込む現地知見（シビックテックもばら 篠田さん）

茂原市の発災直後の動きと、県民に届けるべき情報の型。公開時は公式発表で裏取りする。

| 知見 | サイトへの落とし込み |
|------|----------------------|
| 朝の全市パトロール → 災害対策本部会議という情報の流れ | 被害状況ログに、公式発表を時系列で残す（上書きせず履歴にする） |
| 住宅：床上浸水、崖崩れによる避難。公共：下水処理場ポンプ故障による節水制限 | 市町村ページの「いまの状況」に、住宅被害とライフラインを分けて載せる |
| 住民の問い合わせが避難支援から生活支援へ移る | 市町村ページに「いまのフェーズ」を出す（避難／生活再建） |
| 災害救助法の適用、内閣府の被害状況調査、罹災証明、応急修理の受付 | 生活再建の段取りとして、いまどの段階まで進んでいるかを出す |
| 転居が必要な場合、応急仮設（民間アパート家賃補助・期間の定めあり）か、被災住宅の応急修理かを選ぶ | 県民向けに「分岐」として見せる。金額・期間は公式確認後にのみ記載 |
| 調査から罹災証明まで時間がかかり、申請受付までさらにかかる | 「いま申請できること」と「これから始まること」を分ける。空白期間に何を準備するかを案内する |
| 能登で石川県が導入したタブレット調査により交付が速くなる見込み | 参考情報。千葉県各自治体の導入状況が分かればログに残す。CTZCが調査システムを作る話ではない |
| シビックテックにできることは、速やかな行政情報の収集と伝達拡散 | 支援者向けの中核タスクにする。集めた公式情報を県民向けログと支援策一覧へ載せる |

## 3. 差別化ポイント

### 競争優位性

- **地域に根ざした継続的な団体である** — 単発の有志プロジェクトと異なり、CTZCという母体があり、災害後も活動が続く
- **行政より速く動ける** — 意思決定の階層がなく、その日のうちに作って公開できる
- **入口が二つに分かれている** — 県民は状況と支援策、支援者は協働。混線しない
- **行政情報の収集と拡散に特化する** — 救命や現地ボランティアマッチングは担わない。公式が出した情報を早く、履歴付きで届ける
- **袖ケ浦の先行実装を県全域へ広げる** — 検証済みの QA 型ナビゲーターとデータ差し替え手順を土台にする

### 参入障壁 / Moat

営利事業ではないため参入障壁は本質的に重要ではない。むしろ他団体が真似・流用しやすいことが価値になる（袖ケ浦の事例が公開されていたように）。強いて挙げれば、千葉県内での既存の人的ネットワークと信頼が優位性。

## 4. タイミング

### Why Now

令和8年8月の豪雨が実際に発生した直後であり、支援を必要とする人と、支援したい人が同時に存在している。この時期を逃すと関心が急速に薄れ、次の災害まで動きが止まる。

### 追い風となるトレンド

- 過去の災害（令和元年房総半島台風、令和2年熊本豪雨など）でのシビックテックの実績と、公開されたソースコード・ノウハウが蓄積されている
- 行政のオープンデータ整備が当時より進んでいる

## 5. チームの強み

### Why You

CTZCは千葉県を対象とするシビックテック団体であり、この地域の課題に取り組むことが活動の目的そのもの。千葉県内に生活基盤と人的ネットワークを持つメンバーが当事者として動ける。

### アンフェアアドバンテージ

- 千葉県という地理的スコープに特化した既存コミュニティとSlackという稼働中の連絡基盤
- 同県内の先行事例（シビックテック袖ケ浦）と、公開済みのソース・ローカライズ手順
- 現地の行政プロセスを知るシビックテックもばらとの接点（篠田さん）

## 8. リスクと仮説

### 検証すべき仮説

1. **CTZCメンバーの中に「何かしたい」と思っている人が実際にいる** — ここが空振りなら、そもそも場を作っても人が集まらない
2. **Slackだけでは足りず、蓄積・一覧できる場に価値がある** — 単なる思い込みの可能性がある
3. **投稿された「できそうなこと」が、実際に誰かの手で動き出す** — アイデアが並ぶだけで終わる可能性がある
4. **市町村別の支援策ページは、公式情報へのリンクと要約があれば住民に使われる** — 空のページや古い制度一覧では使われない
5. **シビックテック袖ケ浦のナビゲーターを県全域に拡張できる** — データ構造・許諾・制度の更新負荷がボトルネックになる可能性がある
6. **公式発表を時系列で残すと、県民と支援者の両方に使われる** — 最新だけ見せる公式サイトの補完になる
7. **「いま申請できること」と「これから始まること」を分けると、空白期間の不安が減る** — 篠田さんが指摘した1ヶ月問題への応答

### 主要リスク

| リスク | 対策 |
|--------|------|
| 運営が1名のため、更新が止まる | 全市町村の中身を初日に埋めない。枠は先に出し、中身は優先市町村と協力者で埋める。制度の本文は自作せず公式へリンクする |
| 誤った情報を掲載してしまう | 制度の適用可否は各機関の判断である旨を明示する（袖ケ浦と同じ）。出典と最終確認日を必須にする |
| 誰も投稿せず、空のサイトになる | 立ち上げ時に運営側で数件のアイデアを投稿しておく。Slackで直接呼びかける |
| 行政や他団体の取り組みと重複する | 袖ケ浦版は「取り込む・拡張する」対象。公開前に連絡し、クレジットと共同の形を決める。県・社協の既存まとめがある場合はリンクする |
| 全市町村54分の制度調査が一人では終わらない | 共通（国・県）と市町村固有を分離する。空の市町村は「準備中＋公式リンク」で出し、募集項目として協働編集する |
| 災害の関心が薄れ、活動が自然消滅する | 「今後の災害対策」という平時のテーマを含めておき、復興フェーズ後も継続する意味を持たせる |

### 撤退・転換の判断基準 [仮]

立ち上げから1ヶ月時点で、運営者以外からの投稿が1件もなく、Slack経由の反応もない場合は、ポータルという形式を見直す。
