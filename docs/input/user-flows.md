# ユーザーフロー

MVP には認証機能がない。すべて閲覧から始まる。**最初の分岐は「県民か、支援者か」。**

## 0. 入口の分岐

1. トップを開く
2. 二つの入口から選ぶ
   - 県民の方へ（被害の経過と、いまの支援策）
   - 支援・協働する方へ（情報共有と参加）
3. 選んだ面の中だけを辿る。もう一方へはフッターなど二次導線のみ

**成功条件：** 県民が Slack やアイデア募集に迷い込まず、支援者が生活再建の手続きページを「自分の作業場」と勘違いしない

---

## 県民向け 1：自分の市町村のいまを見る

**目的：** 被害の過去ログと、いま受けられる支援策にたどり着く

**フロー：**

1. 「県民の方へ」を選ぶ
2. 市町村一覧から自分の自治体を選ぶ
3. 市町村ページで次を見る（この順が望ましい）
   - いまのフェーズ（避難／生活再建など）
   - いま受けられる支援策
   - 被害状況のログ（新しい順。過去も残る）
   - 生活再建の段取り（罹災証明の前後、修理か仮設かの分岐）
   - 県・国の支援策への導線
4. 気になる項目の公式ページへ進む

**成功条件：** 公式へ遷移できる。サイト上で「必ず受けられる」「何日で証明書が出る」と断定しない

---

## 県民向け 2：生活再建の次の一手を知る

**目的：** 問い合わせが生活支援に移ったあと、今どの段で、次に何が始まるかを知る

**フロー：**

1. 市町村ページの段取りを見る
2. 「いま申請できること」と「これから（罹災証明のあと）」が分かれていることを確認する
3. 公式の罹災証明・応急修理・応急仮設の案内へ進む

**成功条件：** 空白期間でも、準備として公式の何を見ればよいかが分かる

---

## 支援者向け 1：参加を決める

**目的：** 「何かしたい」人が、行政情報の収集など具体的な仕事に手を挙げる

**フロー：**

1. 「支援・協働する方へ」を選ぶ
2. CTZC が何をやろうとしているか（行政情報の収集と伝達拡散）を読む
3. やること一覧で募集中を見る（例：○○市の公式発表をログに載せる）
4. Slack で表明する
5. スプレッドシートが更新され、担当者が一覧に載る

**成功条件：** 担当者名が入り、ステータスが進行中になる

---

## 支援者向け 2：アイデアを出す／意見を届ける

1. 支援者面の Slack または意見箱へ
2. 運営がシートに追記する
3. やること一覧に載る

県民が誤って意見箱を「罹災証明の申請窓口」だと思わないよう、県民面の意見箱は「このサイトへの指摘」に限定し、申請は公式へ送る旨を書く。
