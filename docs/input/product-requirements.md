# プロダクト要件

## 1. プロダクト概要

### プロダクト形態

Webサイト（ブラウザで閲覧）。アプリのインストールは不要。

**一つのサイトに二つの面を持つ。トップで入口を明確に分ける。**

| 面 | 誰向け | 何をするか |
|----|--------|------------|
| 県民向け | 千葉県民・被災者 | 被害状況の過去ログと、いま受けられる支援策の一覧 |
| 支援者向け | CTZC・有志 | 集まって情報共有し、行政情報の収集と伝達拡散を分担する |

県民向けの画面に Slack 募集を大きく出さない。支援者向けの画面に生活再建の手続きを混ぜない。フッターの「もう一方の入口」だけを残す。

### 対応プラットフォーム

スマートフォンを第一に考える。PCでも問題なく閲覧できること。

### 利用環境

- 被災地域からのアクセスを想定し、通信環境が悪くても開けること
- ログイン不要で誰でも閲覧できること

## 2. コアバリュー

### このプロダクトの核となる価値

行政が出した情報を、速やかに集め、県民には履歴付きで渡し、支援者には「今何を拾うか」が見える形で渡すこと。

### Aha Moment

- 県民：自分の市町村で「いまのフェーズ」と「いま申請できること」が分かった瞬間
- 県民：昨日までの被害ログが残っていて、公式サイトでは消えた経緯を辿れた瞬間
- 有志：「この市の公式発表をログに載せる」仕事があり、手を挙げられる瞬間

## 3. 主要機能

詳細は [機能一覧](./feature-list.md) を参照。

### 必須機能（Must Have）

- トップ：県民向け／支援者向けの二つの入口（同列、どちらが自分か迷わない文言）
- **県民向け**
  - 市町村一覧と全市町村の個別ページ枠
  - 市町村ごとの被害状況ログ（日時・出典・公式URL。上書きせず追記）
  - いま受けられる支援策の一覧（受付中／準備中／終了を分ける）
  - 生活再建の段取り（罹災証明の前後、応急修理と応急仮設の分岐）
  - 千葉県全域の支援策（共通レイヤー）
- **支援者向け**
  - 取り組みの説明、Slack 参加、意見箱
  - アイデア／やること一覧（行政情報の収集を中核タスクにする）
  - 支援者用の情報リンク・先行事例

### 推奨機能（Should Have）

- 質問に答えると適用可能性のある制度が一覧されるナビゲーター（袖ケ浦／SaigaiAId）
- 「いまのフェーズ」表示（避難／生活再建、災害救助法、罹災証明の受付状況）
- サイト上での投稿・編集（現状は外部ツール運用）

### あれば嬉しい機能（Nice to Have）

- 地図ダッシュボード
- 多言語対応

## 4. データと編集の方針

### 編集方式：外部ツール連携（C案）

サイト上に編集機能は作らない。運営と協力者はスプレッドシートを共同編集し、サイトはその内容を読み取って表示する。県民向けのログと支援策、支援者向けのやることリストはシートを分ける。

### 支援策データの構造

国・県の制度を全市町村ページにコピーしない。3層にする。

| 層 | 内容 | 掲載場所 |
|----|------|----------|
| 国 | 内閣府などの被災者支援制度 | 共通。全市町村から参照 |
| 千葉県 | 県の見舞金・減免・相談窓口など | 「県全域の支援策」ページ |
| 市町村 | 独自策、窓口、ライフライン制限、罹災証明の案内 | 各市町村の個別ページのみ |

### 被害状況ログのデータ

公式発表を時系列で残す。最新一件で上書きしない。これが県民向け「過去ログ」の本体である。

| 項目 | 内容 | 必須 |
|------|------|------|
| 市町村 | | ○ |
| 日時 | 発表または確認の日時 | ○ |
| 種別 | 住宅被害／避難／ライフライン／本部会議／制度の動き など | ○ |
| 要約 | 1〜3文。断定せず公式の表現に寄せる | ○ |
| 公式URL | 一次情報 | ○ |
| 確認者 | 支援者側で誰が拾ったか | |

### 生活再建の段取り（県民向けの共通型）

篠田さん報告を型にし、市町村ごとの進捗だけを差し替える。金額・日数は公式確認後。

```
避難・応急対応
    ↓
災害救助法の適用（適用された市町村に明示）
    ↓
被害状況調査（内閣府の調査。タブレット導入の有無は参考）
    ↓
罹災証明書の交付  ← 多くの手続きの起点
    ↓
分岐：応急仮設住宅（民間賃貸の家賃補助など）
   または 被災住宅の応急修理
```

県民ページでは、いまどの段にあるかと、「いま申請できる／まだ始まっていない」を分ける。茂原市では調査から罹災証明まで時間がかかり、申請受付までさらにかかる、という空白が課題である（**[要公式確認]**）。その間に県民が見られるのは、公式の最新と、ログに残した経緯である。

### 情報の取り扱い原則

1. **一次情報を自作しない** — 被害も制度も公式へリンクする。適用可否は各機関の判断
2. **出典と日時を明記する**
3. **上書きせずログに残す** — 最新と履歴を両方見せる
4. **「いま」と「これから」を分ける**
5. **国・県の共通制度と市町村固有を分ける**
6. **空でも枠は出す**
7. **入口を混ぜない** — 県民面と支援者面を同じ画面の主役にしない

袖ケ浦市は既存ナビへの案内を優先する。茂原市は優先してログと支援策を埋める市町村とする。

実装の参考は [SaigaiAId](https://github.com/kanawha-st/SaigaiAId) と [ローカライズ手順](https://civictechsodegaura.org/archives/597)。QA 型 UI は Phase 2。

## 5. 非機能要件

### パフォーマンス

表示は軽量に。画像は最小限。通信環境が悪い状況での閲覧を想定する。

### セキュリティ

MVP では認証機能を持たない。意見箱で個人情報を収集しない。

### スケーラビリティ

静的な配信を基本とし、報道拡散時の負荷に耐える。

### 運用性

運営1名でも、ログは「公式URLと日時と要約」だけ追記すれば足りる形にする。
