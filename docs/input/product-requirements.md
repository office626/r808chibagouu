# プロダクト要件

## 1. プロダクト概要

### プロダクト形態

Webサイト（ブラウザで閲覧）。アプリのインストールは不要。

**一つのサイトに二つの面を持つ。トップで入口を明確に分ける。**

| 面 | 誰向け | 何をするか |
|----|--------|------------|
| 県民向け | 千葉県民・被災者 | 被害状況の過去ログと、いま受けられる支援策の一覧 |
| 支援者向け | CTZC・有志 | 集まって情報共有し、行政情報の収集と伝達拡散を分担する |

県民向けの画面に Slack 募集を大きく出さない。支援者向けの画面に生活再建の手続きを混ぜない。フッターの「もう一方の入口」だけを残す。

### 対応プラットフォーム

スマートフォンを第一に考える。PCでも問題なく閲覧できること。

### 利用環境

- 被災地域からのアクセスを想定し、通信環境が悪くても開けること
- ログイン不要で誰でも閲覧できること

## 2. コアバリュー

### このプロダクトの核となる価値

行政が出した情報を、速やかに集め、県民には履歴付きで渡し、支援者には「今何を拾うか」が見える形で渡すこと。

### Aha Moment

- 県民：自分の市町村で「いまのフェーズ」と「いま申請できること」が分かった瞬間
- 県民：昨日までの被害ログが残っていて、公式サイトでは消えた経緯を辿れた瞬間
- 有志：「この市の公式発表をログに載せる」仕事があり、手を挙げられる瞬間

## 3. 主要機能

詳細は [機能一覧](./feature-list.md) を参照。

### 必須機能（Must Have）

- トップ：県民向け／支援者向けの二つの入口（同列、どちらが自分か迷わない文言）
- **県民向け**
  - 市町村一覧と全市町村の個別ページ枠
  - 市町村ごとの被害状況ログ（日時・出典・公式URL。上書きせず追記）
  - いま受けられる支援策の一覧（受付中／準備中／終了を分ける）
  - 生活再建の段取り（罹災証明の前後、応急修理と応急仮設の分岐）
  - 千葉県全域の支援策（共通レイヤー）
- **支援者向け**
  - 取り組みの説明、Slack 参加、意見箱
  - アイデア／やること一覧（行政情報の収集を中核タスクにする）
  - 支援者用の情報リンク・先行事例

### 推奨機能（Should Have）

- 質問に答えると適用可能性のある制度が一覧されるナビゲーター（袖ケ浦／SaigaiAId）
- 「いまのフェーズ」表示（避難／生活再建、災害救助法、罹災証明の受付状況）
- サイト上での投稿・編集（現状は外部ツール運用）

### あれば嬉しい機能（Nice to Have）

- 地図ダッシュボード
- 多言語対応

## 4. データと編集の方針

### 収集と更新（自動・1日1回）

県民向けの被害ログと支援策は、**行政機関および報道機関の公開情報を収集し、1日1回自動で更新する。**

| 項目 | 方針 |
|------|------|
| 収集元 | 行政（国・千葉県・各市町村の公式サイト、防災ポータル、RSS 等）と報道（許可された配信・RSS・公式ニュースページ） |
| 頻度 | 1日1回（日本時間 **6:00**。UTC cron は `0 21 * * *`） |
| 反映 | 収集ジョブの成功後にサイトを再生成して公開する |
| 表示 | 各件に出典区分（行政／報道）、媒体名、日時、元記事・発表の URL |
| 本文 | 記事全文は転載しない。見出しと短い要約、リンクにとどめる |
| 衝突 | 事実・制度・受付状態は行政を優先する。報道は「報道による」と明示してログに残せる |
| 対象の広げ方 | 初日はレベル5対象および流山市を厚く取る。全市町村枠は維持する |

人手のシートは [この Google スプレッドシート](https://docs.google.com/spreadsheets/d/1_dHZHMLvTx6iTCzwvbw6U9cTHjTIH_6RlEob81Ng7KM/edit?usp=sharing)（所有者 `tutti666@gmail.com`）を使う。**リンクを知っている人は閲覧可。編集は招待した人のみ。** 日次ジョブもこの閲覧権限で読む。用途は次のとおり。

- 収集先 URL・ドメインの許可リスト（初版は [`source-allowlist.md`](./source-allowlist.md)）
- 自動では取りこぼした件の補完、誤った市町村紐づけの訂正
- 支援者向けのやること一覧
- ジョブが失敗したときの手動公開

支援者の中核は「全部を手で拾う」ことではなく、許可リストの整備、誤りの指摘、自動更新が止まったときの対応になる。

### 支援策データの構造

国・県の制度を全市町村ページにコピーしない。3層にする。

| 層 | 内容 | 掲載場所 |
|----|------|----------|
| 国 | 内閣府などの被災者支援制度 | 共通。全市町村から参照 |
| 千葉県 | 県の見舞金・減免・相談窓口など | 「県全域の支援策」ページ |
| 市町村 | 独自策、窓口、ライフライン制限、罹災証明の案内 | 各市町村の個別ページのみ |

### 被害状況ログのデータ

行政・報道の公開情報を時系列で残す。最新一件で上書きしない。1日1回の自動収集が本体で、人手の追記は補完である。

| 項目 | 内容 | 必須 |
|------|------|------|
| 市町村 | 紐づけ。県全域の場合は共通 | ○ |
| 日時 | 発表または記事の日時 | ○ |
| 種別 | 住宅被害／避難／ライフライン／本部会議／制度の動き など | ○ |
| 要約 | 1〜3文。転載ではなく要約 | ○ |
| 出典URL | 行政発表または報道の元ページ | ○ |
| 出典区分 | 行政／報道 | ○ |
| 媒体名 | 例: 千葉県、○○市、○○新聞 | ○ |
| 取得日時 | ジョブが取り込んだ日時 | ○ |
| 確認者 | 人手で訂正した場合 | |

### 生活再建の段取り（県民向けの共通型）

とある行政の知見を型にし、市町村ごとの進捗だけを差し替える。金額・日数は公式確認後。個人名・特定自治体の内部情報は書かない。

```
避難・応急対応
    ↓
災害救助法の適用（適用された市町村に明示）
    ↓
被害状況調査（内閣府の調査。タブレット導入の有無は参考）
    ↓
罹災証明書の交付  ← 多くの手続きの起点
    ↓
分岐：応急仮設住宅（民間賃貸の家賃補助など）
   または 被災住宅の応急修理
```

県民ページでは、いまどの段にあるかと、「いま申請できる／まだ始まっていない」を分ける。とある行政では、調査から罹災証明まで時間がかかり、申請受付までさらにかかる、という空白が課題である（**[要公式確認]**）。その間に県民が見られるのは、公式の最新と、ログに残した経緯である。

### 情報の取り扱い原則

1. **一次情報を自作しない** — 被害も制度も、行政または報道の公開ページへリンクする。適用可否は各機関の判断
2. **出典と日時を明記する** — 行政と報道を必ず区別する
3. **上書きせずログに残す** — 最新と履歴を両方見せる。自動更新も追記であり、過去件を消さない
4. **「いま」と「これから」を分ける** — 制度の受付状態は行政ソースを優先する
5. **国・県の共通制度と市町村固有を分ける**
6. **空でも枠は出す**
7. **入口を混ぜない**
8. **報道の全文は転載しない** — 見出し・要約・リンク。著作権と各社の利用規約に従う
9. **1日1回の自動更新を止めて見せない** — 最終取得日時を出し、ジョブ失敗時は前回データを残す

袖ケ浦市は既存ナビへの案内を優先する（ソース再利用は作成後に確認）。初日にログと支援策を埋める市町村は、警戒レベル5（大雨特別警報）が出た自治体および流山市とする。一覧は報道時点のもので、気象庁の確定で更新する。

**初日ログ対象 [要公式確認]**（[ウェザーニュース 2026-08-13](https://weathernews.jp/news/202608/130321/) のレベル5大雨特別警報対象 ＋ 流山市）

- レベル5大雨: 千葉市、市川市、船橋市、松戸市、茂原市、佐倉市、東金市、習志野市、柏市、市原市、八千代市、我孫子市、鎌ケ谷市、四街道市、八街市、印西市、白井市、山武市、大網白里市、九十九里町、白子町、長柄町
- 追加: 流山市（レベル5対象外でも初日対象とする）

※ 対象は発表時刻によって増減した。公開前に気象庁の発表履歴で確定する。市町村名の掲載は公式の警報対象であり、内部情報の特定には使わない。

## 5. 非機能要件

### パフォーマンス

表示は軽量に。画像は最小限。通信環境が悪い状況での閲覧を想定する。

### セキュリティ

MVP では認証機能を持たない。意見箱で個人情報を収集しない。

### スケーラビリティ

静的な配信を基本とし、報道拡散時の負荷に耐える。

### 運用性

運営1名でも回るよう、県民向け本文の主更新は自動収集（1日1回）に任せる。人手は許可リストと例外の訂正に限る。
