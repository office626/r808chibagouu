# システム要件定義書

## システム概要

本システムは、令和8年8月千葉豪雨を対象に、CivicTechZenChiba（CTZC）が運営するWebポータルである。トップで入口を二つに分ける。県民向けは、市町村ごとの被害状況ログ（過去〜現在）と、いま受けられる支援策・生活再建の段取りを公式出典付きで見せる。支援者向けは、有志が行政情報の収集と伝達拡散を分担する場（やること一覧、Slack、意見箱）である。一次情報は自作せず、静的配信を基本に、運営1名・無償・即時公開の制約の下で動かす。

1. システムの目的
   - 解決する具体的な課題
     - 公式発表が上書きされ、被害の経過が残らない
     - 国・県・市町村の支援策が分散し、「いま自分の自治体で使えるもの」が分からない
     - 生活再建（罹災証明の前後、応急修理か応急仮設か）の段取りが見えない
     - 有志の意思が Slack で流れ、何を拾えばよいかが見えない
   - 目標とする成果
     - 県民が自分の市町村ページで、ログといまの支援策にたどり着ける
     - 支援者が「この市の公式発表をログに載せる」仕事に手を挙げられる
     - トップで県民と支援者が迷わず分かれる
   - 期待されるビジネスインパクト
     - 非営利のため収益インパクトはない。行政情報の空白期間を埋め、生活再建の機会損失を減らす。CTZC の活動が公開され、協働の入口になる

2. 主な機能
   - コア機能（3-5 個）
     - 県民／支援者の二つの入口
     - 市町村ページ（被害ログ＋いまの支援策＋生活再建の段取り）
     - 千葉県全域・国の支援策（共通レイヤー。市町村へ複製しない）
     - 支援者向けやること一覧（行政情報の収集が中核）
     - Slack 参加と意見箱
   - 差別化機能（2-3 個）
     - 公式発表を上書きせず時系列で残すログ
     - 「受付中／準備中／終了」でいま申請できることを分ける
     - 全市町村のページ枠を先に出し、中身を分担して埋める
   - 付加価値機能（1-2 個）
     - QA 型支援制度ナビゲーター（袖ケ浦 SaigaiAId の拡張、Phase 2）
     - いまのフェーズ表示（災害救助法、罹災証明の受付状況、Phase 2）

3. 提供する価値
   - ユーザーにとっての直接的価値
     - 県民：自分の市の経緯といまの手続きが、公式への導線付きで分かる
     - 支援者：今人手の要る収集作業が見え、オンラインで参加できる
   - ビジネスにとっての価値
     - CTZC の活動が検証可能な形で残り、協力者を受け入れられる
   - 社会的価値
     - 行政サイトを置き換えず補完する。申請は公式窓口へ。有志運営であることを明示する

4. 実現方法の概要
   - 主要なテクノロジー要素
     - Next.js（App Router）による静的生成（SSG）と TypeScript
     - コンテンツは、行政・報道の公開情報を1日1回自動収集し、ビルドして静的公開する
     - 許可リストと訂正用に [Google スプレッドシート](https://docs.google.com/spreadsheets/d/1_dHZHMLvTx6iTCzwvbw6U9cTHjTIH_6RlEob81Ng7KM/edit?usp=sharing)（`tutti666@gmail.com`）を使う
     - ホスティングは Vercel の無料枠。認証は MVP では持たない
   - 重要なインテグレーションポイント
     - 日次ジョブ（GitHub Actions 等）による行政・報道フィードの取得
     - 許可リスト用スプレッドシート
     - Slack（リンクのみ）、意見箱（外部フォーム）
     - 各発表・記事の URL（全文は転載しない）
   - スケーラビリティへの考慮
     - 閲覧は静的 HTML。報道拡散時もオリジン負荷をほぼゼロにする
     - 千葉県全市町村（54）は静的パスとして事前生成する

## 機能要件

### FR-00 二つの入口

- トップに「県民の方へ」「支援・協働する方へ」を同列に置く
- 県民面の主操作に Slack 参加を置かない
- 支援者面の主操作に罹災証明の申請案内を置かない
- もう一方の面へはヘッダー／フッターの二次導線のみ
- 全ページに最終更新日と「有志運営・公式ではない・申請は公式へ」を出す

### FR-10 県民向けホームと市町村一覧

- 市町村から探す、県の支援策、公式リンク集への導線
- 全市町村を一覧し、個別ページへ進める（中身が空でも選べる）
- 未整備の市町村は「準備中」と公式 HP リンクを出す

### FR-11 市町村個別ページ

同一テンプレート。全市町村分の URL を持つ。

1. いまの要約（ログ最新件と一致）
2. いま受けられる支援策（受付中を上に。準備中・終了は分ける）
3. 被害状況ログ（新しい順。過去件を消さない）
4. 生活再建の段取り（共通の型。市町村の進捗だけ差し替え）
5. 県・国の支援策への参照（本文を複製しない）
6. 公式の災害・支援ページへのリンク
7. 未整備時は、当該市の情報収集を支援者面の募集へつなぐ案内（県民面では小さく）

### FR-12 被害状況ログ

一件あたり必須: 市町村、日時、種別、要約（1〜3文）、出典 URL、出典区分（行政／報道）、媒体名、取得日時。任意: 人手の確認者。

- 最新一件で上書きしない。日次ジョブは追記する
- 出典 URL がない件は公開しない
- 報道の全文は転載しない
- 同一 URL は重複登録しない
- ページ上部の「いま」は最新件と一致させる
- 制度・受付状態の断定は行政ソースを優先する

### FR-15 日次自動収集

- 許可リスト上の行政機関・報道機関から、1日1回（**6:00 JST** / cron `0 21 * * *` UTC）情報を取得する
- 許可リストの初版は `docs/input/source-allowlist.md`
- Yahoo!ニュース RSS および NHK 公式 RSS は利用条件のため自動収集に使わない
- 成功後にサイトを再生成して公開する
- 失敗時は前回の公開データを維持し、最終取得日時を更新しない（または失敗を明示する）
- SNS の個人投稿は収集対象にしない
- 収集先の追加・停止はシートの許可リストで行う

### FR-13 支援策（3層）

| 層 | 掲載 |
|----|------|
| 国 | 共通。全市町村から参照 |
| 千葉県 | 「県全域の支援策」ページ。全市町村から参照 |
| 市町村 | 当該ページのみ |

制度カード必須: 名称、対象の要約、実施主体、公式 URL、最終確認日、受付状態（受付中／準備中／終了）、公開状態。金額・日数は公式確認済みのときだけ表示（A8）。適用可否は各機関の判断である旨を出す。

### FR-14 生活再建の段取り

共通の型:

避難・応急 → 災害救助法（適用市町村に明示）→ 被害状況調査 → 罹災証明書 → 応急仮設（民間賃貸の家賃補助等）または被災住宅の応急修理。

「いま申請できること」と「これから」を分ける。調査システムそのものは本システムの対象外。

### FR-20 支援者向けホーム

- 役割の説明（行政・報道の日次自動収集を支え、誤りを直す）
- Slack 参加（既存チャンネルへのリンク）を最も目立たせる
- やること一覧への導線、意見箱への導線
- 先行事例（袖ケ浦ナビ、能登版）へのリンク（Phase 2 でも可）

### FR-21 やること一覧

必須: タイトル、説明、ステータス（募集中／進行中／完了）、登録日。任意: 担当者、対象市町村、関連リンク。

- 公開時に許可リスト整備・誤紐づけ訂正などの募集を1件以上入れる
- 0件のときは参加を促す文言を出す
- シート更新がサイトに反映されること（反映遅延はビルド間隔に依存。仮定: 再ビルドまたは ISR で数分〜1時間）

### FR-22 意見箱

- ログイン不要の外部フォーム
- 申請窓口ではないと明記する
- 送信完了が送った人に分かること

### FR-30 コンテンツ編集（MVP）

- サイト上の投稿・編集・認証は作らない
- 県民向けログ／支援策と、支援者向けやることはシートを分ける
- 有志が1市町村ずつ担当できる列構造にする

### FR-40 Phase 2 以降（本要件では実装しないが境界を固定する）

- QA 型ナビゲーター（SaigaiAId のローカライズ）
- いまのフェーズの全市町村表示
- サイト上編集とログイン
- 地図ダッシュボード、多言語

## 非機能要件

根拠は仮定 A1〜A3。初期の定常利用者は支援者数十人＋初日ログ対象市町村の閲覧。ピークは報道・SNS 拡散時。

| ID | 項目 | 要件 | 根拠 |
|----|------|------|------|
| NFR-P1 | 初期表示 | 主要画面の LCP を目安 3 秒以内（4G 相当）。画像は最小 | 被災地の通信、モバイル第一 |
| NFR-P2 | ページ重量 | 初回転送は小さく保つ。装飾画像・動画・ウェブフォントの多用をしない | 同上 |
| NFR-P3 | 生成 | 全市町村ページをビルド時に静的化する | 54ページ規模。動的 DB 問い合わせを閲覧経路に置かない |
| NFR-S1 | 認証 | MVP は認証なし（閲覧のみ） | プロダクト要件。Clerk は Phase 2 |
| NFR-S2 | 個人情報 | 意見箱で氏名・住所・被害状況の詳細を必須にしない。申請は公式へ | 有志サイトが個人データを抱えない |
| NFR-S3 | なりすまし | 「行政の公式ではない」を全ページに出す | 誤認リスク |
| NFR-S4 | コンテンツ改ざん | [運用シート](https://docs.google.com/spreadsheets/d/1_dHZHMLvTx6iTCzwvbw6U9cTHjTIH_6RlEob81Ng7KM/edit?usp=sharing) はリンクを知っている人が閲覧可。編集は招待者のみ | 確定 |
| NFR-A1 | 可用性 | 静的ホスティングの SLA に乗せる。障害時も公式リンク集が読めるフォールバックを目指す | 災害時に落ちないこと |
| NFR-A2 | ピーク | 静的配信により、数千〜数万 PV のバーストでもオリジン増強を不要とする（A1） | 報道リスク |
| NFR-O1 | 更新負荷 | 県民向け本文の主更新は日次ジョブ。人手は許可リストと例外 | 運営1名 |
| NFR-O2 | 鮮度 | 毎日 6:00 JST に自動更新。失敗時は前回データを維持し、最終取得日時で分かるようにする | 確定 |
| NFR-O3 | リンク切れ | 取得時に到達できない URL は新規掲載しない。既存件はログに残す | 古い災害サイトの失敗 |
| NFR-C1 | コスト | 月額 0 円を目標（Vercel Hobby、GitHub Actions、Sheets、Forms 無料枠） | 予算なし |
| NFR-C2 | アクセシビリティ | 文字サイズ大きめ、色だけに状態を頼らない、コントラスト確保 | 高齢者を含む県民 |
| NFR-L1 | 法務 | 制度の断定をしない。報道全文を転載しない。個人名を出さない。袖ケ浦クレジットは作成後確認 | 著作権・誤認 |

## 技術スタック

特指定がないため、提示されたモダンスタックを第一候補とし、制約（1名、即時、無償、MVP は認証なし・シート編集）に対して採否を分けた。

### 採用（MVP）

| 層 | 技術 | 選定理由 |
|----|------|----------|
| フロントエンド | Next.js (React) App Router | 市町村×静的パスの生成、型付きコンポーネント、シビックテックでの採用例が多い。App Router の `generateStaticParams` で54市町村を SSG できる |
| 言語 | TypeScript | 制度カード・ログの項目漏れを型で防ぐ。協働時の読みやすさ |
| ホスティング | Vercel | Next.js との相性、無料枠、Git 連携で PR レビューできる。すでに GitHub 公開済み |
| コンテンツ | 日次収集結果をリポジトリまたはビルド成果に保存し、SSG する | 閲覧経路に DB を置かない。履歴が Git に残る |
| 収集ジョブ | GitHub Actions の cron（1日1回） | 無料枠。失敗がログに残る。成功後にデプロイ |
| 許可リスト | [Google スプレッドシート](https://docs.google.com/spreadsheets/d/1_dHZHMLvTx6iTCzwvbw6U9cTHjTIH_6RlEob81Ng7KM/edit?usp=sharing) | リンクを知っている人は閲覧可。編集は招待制 |

### 採用しない／遅らせる

| 層 | 第一候補 | 本プロジェクトでの判断 |
|----|----------|------------------------|
| 認証 Clerk | MVP 不採用 | 閲覧専用。コストと実装が即時公開と衝突する。サイト内編集を始める Phase 2 で再評価 |
| データベース supabase (PostgreSQL) | MVP 不採用、Phase 2 候補 | ログと制度は表形式で足りる。同時書き込みと行レベル権限が必要になったら導入。その時点で Clerk または Supabase Auth を比較する |
| バックエンド（常時起動 API） | MVP 不採用 | 収集は日次バッチ。意見箱は外部フォーム。閲覧は静的ファイル |

### Phase 2 で再評価する組み合わせ

- データ量・編集衝突が増えたら Supabase（`logs`, `measures`, `tasks`, `municipalities`）
- サイト上編集が必要なら Clerk または Supabase Auth（支援者のみ。県民はログインしない）
- QA ナビは SaigaiAId（Vue）を iframe／移植するか、同等 QA を Next.js で再実装する。依存とライセンスを導入前に確認する

### 周辺ツール（MVP）

| 用途 | 技術 |
|------|------|
| 意見箱 | Google フォーム等（個人情報を必須にしない） |
| 連絡 | 既存 Slack チャンネル（埋め込み API は不要） |
| CI / 日次収集 | GitHub Actions（push でデプロイ、cron で1日1回収集） |
| 監視 | Actions の失敗通知。最終取得日時をサイトに出す |

この構成は、機能要件（二面・全市町村 SSG・ログ追記）、非機能（軽量・ピーク耐性・月額0円）、チーム（1名＋シート編集者）、保守（GitHub で検証可能）と整合する。Clerk + Supabase を初日に入れると、認証・RLS・環境変数の整備がクリティカルパスになり、即時公開の制約を破る。

## 開発ロードマップ

フェーズ分けの根拠: MVP で入口と「行政・報道を1日1回拾って見せる」回路を検証する。認証・DB・QA ナビは後回し。地図はデータ整備後。調査システムは対象外。

| フェーズ | 時期 | 成果 | 含めないもの |
|----------|------|------|----------------|
| 0 準備 | 公開前 | 許可リストを [運用シート](https://docs.google.com/spreadsheets/d/1_dHZHMLvTx6iTCzwvbw6U9cTHjTIH_6RlEob81Ng7KM/edit?usp=sharing) へ載せる。気象庁のレベル5リスト確定 | |
| 1 MVP | 即時 | 二入口、日次自動収集、県民（全市町村枠＋初日対象のログと支援策＋段取り）、支援者（ホーム、Slack、やること、意見箱）、最終取得日時 | 認証、DB、QA、地図、全文転載 |
| 2 充足 | 〜1ヶ月 | 市町村分担入力、受付状態の運用定着、QA ナビ、フェーズ表示。必要なら Supabase | 地図、多言語 |
| 3 拡張 | 状況次第 | 地図等の見える化、サイト内編集 | 罹災調査そのもの |

成功の定義（MVP）は入力どおり。トップで入口が分かれること、運営者以外の手挙げ、初日ログ対象に出典付きログと支援策があること。

## リスク分析

### 技術的

| リスク | 対策 |
|--------|------|
| 日次ジョブが失敗する | 前回スナップショットでサイトを維持。最終取得日時で停止が分かる。Actions の失敗を通知する |
| サイト構造変更で取得できなくなる | RSS・公式フィードを優先し、HTML の場当たり取得に依存しすぎない |
| 報道全文の転載になる | 見出し・要約・リンクのみ。許可リスト外は取らない |
| 市町村の誤紐づけ | 支援者が訂正できる。県全域件は共通に落とす |
| SaigaiAId のスタックが Next.js と違う | Phase 2 で移植コストを見積もる。MVP は一覧で代替 |
| Vercel / Actions 無料枠の制限 | 1日1回に抑える。監視する |

## UI/UXの方向性

後続の詳細設計のインプットとする。ワイヤーフレームは本ドキュメントでは作らない。

- **デザインコンセプト**: 実用一辺倒。装飾より読みやすさと速さ。開いた瞬間に入口が分かる
- **トーン＆マナー**: 落ち着いた、行政公式ではないが信頼できる。軽薄なイラストや過度なアニメーションは使わない。県民面は手続き案内、支援者面は協働の作業場、とトーンを分ける（色だけに頼らないラベル）
- **ターゲットデバイス**: モバイルファースト。PC でも読める。通信が悪い環境を想定
- **参考サイト/アプリ**:
  - [シビックテック袖ケ浦 災害支援ナビゲーター](https://civictechsodegaura.org/saigai/)
  - [能登半島地震版 災害支援ナビゲーター](https://civictechsodegaura.org/noto/)
  - [東京都 新型コロナウイルス感染症対策サイト](https://stopcovid19.metro.tokyo.lg.jp/)（情報密度とオープンな運営の見せ方）
- **画面の骨格**: トップ（二入口）→ 県民ホーム／支援者ホーム → 市町村ページ（いま／ログ／段取り）またはやること一覧。詳細は `docs/input/ui-ux-direction.md`
- **必須の UI 要素**: 受付状態とやることステータスは色と文字の両方。ログは日時と出典区分が先に目に入る。最終取得日時を県民面に出す。主ボタンは各面で一つに絞る（県民＝市町村から探す、支援者＝Slack）
- **コピーの制約**: 制度を「必ず受けられる」と書かない。「可能性」「公式で確認」を使う
